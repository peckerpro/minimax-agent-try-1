## Day 6 — MCP protocol adapters

**Goal**: hello-agent can both **consume** external MCP servers (Claude Desktop, filesystem, etc.) and **expose** its 11 built-in tools as an MCP server. Closes the §6.x "protocols" module.

**Why first**: MCP is foundational — once tools are MCP-shaped, the Web UI (Day 8), the skills system (Day 7), and any external agent can talk to hello-agent through a single contract. Building it first means Day 7/8 build on a stable interface.

**Deliverables**:

| File | Status | Acceptance |
|---|---|---|
| `hello_agent/protocols/__init__.py` | UPDATE | exports `mcp_client`, `mcp_server` |
| `hello_agent/protocols/mcp_client.py` | NEW | `MCPClient(["npx", "-y", "@modelcontextprotocol/server-filesystem", "."]).connect()` registers 6+ filesystem tools; lifecycle: spawn subprocess, init handshake, list_tools, call_tool, clean shutdown |
| `hello_agent/protocols/mcp_server.py` | NEW | `hello-agent mcp serve` runs stdio MCP server exposing all 11 built-in tools; JSON-serialized results, `ERROR: <msg>\n<hint>` on failure |
| `hello_agent/cli/mcp.py` | NEW | subcommands: `mcp serve` (stdio), `mcp connect -- <cmd> [args...]` (consume + register) |
| `hello_agent/tools/registry.py` | UPDATE | `register_mcp_server(client)` adds remote tools; `execute()` routes to MCP when tool is remote; circuit-breaker applies across MCP calls |
| `tests/test_protocols/test_mcp_client.py` | NEW | mock MCP server fixture; test `list_tools()` + `call_tool()` round-trip; test subprocess lifecycle + error handling |
| `tests/test_protocols/test_mcp_server.py` | NEW | spawn stdio server, send init + tools/list + tools/call, parse responses |
| `tests/test_protocols/test_registry_mcp_integration.py` | NEW | registry.execute() routes correctly when tool is MCP-backed |

## Day 7 — Skills system (SKILL.md format)

**Goal**: hello-agent can load `SKILL.md`-formatted skill packs from `~/.hello_agent/skills/` + builtins. Closes the §6.x "skills" module and lays the foundation for the v0.3+ plugin system (a skill is just a SKILL.md; a plugin is a SKILL.md + a Python module).

**Why second**: Skills are how non-developer users add domain knowledge (file_organize, daily_review, obsidian_lookup) without writing Python. It depends on the tool registry (Day 2) and arguably the agent loop (Day 3), but doesn't need MCP or the Web UI. Putting it before Day 8 lets the Web UI surface "what skills are loaded" as a first-class concept.

**Deliverables**:

| `hello_agent/skills/registry.py` | NEW | `SkillRegistry`; matches user prompt against `triggers` (regex + keyword); resolves tool references through `ToolRegistry`; supports per-session skill activation |
